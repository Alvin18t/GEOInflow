# 浏览流量质量与统计策略

Liekan 保留 Umami 的无 Cookie 默认、SDK 名称、采集字段和响应形状。UV 仍为所选窗口的 `COUNT(DISTINCT session_id)`。默认匿名标识使用 IP、完整 UA、月度盐和可选用户 ID；同一人换网络、浏览器或身份可能产生多个标识，多人共享网络和 UA 也可能合并。该指标代表可观察的匿名标识。

## 采集与去重

跟踪器在页面内按网站 UUID 与实际采集地址注册一次。重复插入同一脚本只发一次初始 PV。不同网站和采集地址分别工作。连续 SPA 跳转立即保存各次地址和来源，延迟发送时读取更新后的页面标题。正常刷新、不同路径和手动事件仍分别计数。

新版跟踪器在安全随机数可用时，为每个逻辑发送附带可选 `payload.eventId` UUID。PostgreSQL 网站事件与性能事件按网站和 UUID 原子去重：相同内容重试返回原事件的会话与访问 ID，确认令牌使用当前时间并保留 Umami 响应形状；同一 UUID 换内容返回 409。事件、属性、收入、质量证据和去重凭据在一个事务内提交，写入失败可用原 UUID 重试。没有 UUID 的旧脚本继续采集，相同内容的独立刷新不会被时间窗口猜测合并。`identify` 保持上游语义，此阶段不使用其 UUID 去重。ClickHouse、短链接和像素继续使用上游流程。

## 分类证据

新增的独立质量表保存分类、原因、规则版本、官方范围版本、证据可用状态、规范化主机名和采集来源。该表不保存原始 IP 或完整 UA。去重凭据只保存内容的 HMAC 摘要。

| 分类 | 证据与默认处理 |
| --- | --- |
| `browser` | UA 与普通浏览器相容；保留。此分类无法证明访问者为真人。 |
| `automated` | 已知自动化 UA，或可信入口 IP 命中新鲜的官方 CIDR；默认排除。 |
| `suspected` | 公共采集中的旧版生产者覆盖字段；默认保留，可单独审计。 |
| `unknown` | 缺少识别证据、历史事件缺少质量记录或主动关闭机器人检测；保留。 |

来源分为公共浏览器、经过网站管理授权的服务端采集、兼容旧版覆盖字段。公共 `/api/send` 继续接受 `ip`、`userAgent`、`browser`、`os`、`device` 字段；这些声明不会提升来源可信度。

官方范围沿用现有 worker 每小时更新的已审核官方来源。浏览事件入库前完成匹配，并保存当时版本。只有配置了 `CLIENT_IP_HEADER` 的受信任入口，或认证服务端的 IP 声明，能用于官方范围判定；任意转发头的存在无法建立信任。入口必须剥离客户端伪造头，并覆盖该配置头。Cloud 模式沿用受信任的 `x-umami-client-ip` 入口。范围超过七天、与事件日期相距超过七天、缺失或异常时，范围证据降级，不据此排除流量。范围刷新失败保留最后成功快照，到期后按过期处理。

短停留、单页、没有点击、数据中心 ASN 和普通 ChatGPT 引荐均不构成此阶段的自动化硬判据。`DISABLE_BOT_CHECK` 保留关闭检测的兼容行为。来源及证据在采集时固化；更新规则作用于后续事件。

## 统一策略与审计

网站所有者或管理者通过 `PUT /api/liekan/websites/{websiteId}/traffic-quality` 设置完整策略：

```json
{"mode":"standard","allowedHostnames":[]}
```

`standard` 默认排除自动化，保留可疑与未知；`strict` 额外排除可疑；`raw` 回看全部原始事件。策略应用于 PostgreSQL 浏览总览、趋势、来源、地域、设备、事件、转化、收入、分享与导出的共同读取层，筛选候选值仅纳入所选窗口内有有效事件的会话，属性和收入跟随其父事件。改变策略同步增加统计版本，跨进程缓存随版本失效。原始事件保持完整，历史缺失证据归为未知。界面布局保持现状。

热图与录制按关联的 `(website_id, session_id, visit_id)` 是否有纳入的访问筛选。没有关联访问的历史记录保留为未知；混合访问包含至少一个纳入事件时保留该访问的录制。安装验证沿用原始采集证据；ClickHouse 使用已有统计及日期范围接口。

`allowedHostnames` 默认为空，采用审计口径。填写列表后按精确主机名筛选，统一大小写、国际化域名、`www` 和端口，不自动扩展子域名。主机名由采集内容提供，这项设置用于统计管理。`raw` 模式保留完整回看能力。审计接口返回实际主机名，便于核对多域名接入。

安装验证与数据来源连接状态依据原始采集记录。有效统计为零时，已收到数据的状态仍然保留；安装响应中的 `browser` 元数据与统计结果使用各自明确的口径。

`GET /api/liekan/websites/{websiteId}/traffic-quality` 返回策略、各类事件/PV/匿名标识数、缺失判定数、当前纳入数与最多 100 条质量明细。可用 `startAt`、`endAt` 毫秒时间戳、`classification` 和 `page` 查询，单次时间跨度最多 366 天。各类 UV 可能有相同访客，不应相加作为整体 UV。

服务端生产者使用 `POST /api/liekan/collect`，携带完整登录令牌或具有该网站管理权限的 API Key，正文继续使用 Umami 网站采集格式。公开分享身份、部分二步验证身份和无网站管理权限身份无法写入或修改策略。公共采集中的 Authorization 字段不会自动建立服务端信任。

## 请求日志与浏览指标

“今日总请求”按网站时区的今日日志窗口计数，只排除已列明的静态后缀。该值包含机器人、API、探测、失败请求及不同方法。人类 UV 使用界面所选浏览窗口，趋势图可以使用独立窗口。日志请求总量与浏览 PV/UV 的单位、来源和窗口各有定义。

本阶段不会补造历史分类，也不会根据截图反推真实偏高比例。可在真实网站上先查看质量审计，核对重复脚本、主机分布、分类占比和所选窗口；原始日志中未采集的证据需要后续采集后验证。

## 本地验证

`pnpm liekan:verify` 包含源码检查、生产构建、独立 Docker 数据库迁移与恢复、API 和视觉验收，随后运行流量质量的真实数据库测试。后者自动创建并清理带唯一归属标签的网络、卷与容器，默认绑定 `127.0.0.1:3324`，不会连接原有应用或数据库。

已构建且 OCI revision 与当前 HEAD 一致的候选镜像，也可单独运行 `pnpm test:traffic-quality`。`LIEKAN_TRAFFIC_IMAGE` 可指定候选镜像，`LIEKAN_TRAFFIC_PORT` 可指定 3300–3399 中空闲的验收端口（排除 3302、3305、3352）。测试覆盖并发重试、事务回滚、分类与范围证据、策略和缓存、统计与关键词导出、原始采集状态、重复迁移、重置及删除。

## 质量面板与策略预览

网站设置的采集设置提供“浏览流量质量”入口。面板使用当前时间范围和时区，分类、来源与主机筛选应用到审计计数和明细。统计对照中的 PV 使用原生网站统计的 `event_type NOT IN (2,5)`，UV 对该集合中的 `session_id` 分别去重。分类汇总保留原有事件级口径。排除 PV 可相加还原原始 PV；排除 UV 表示完全失去纳入事件的匿名标识，分类 UV 不能相加。

`POST /api/liekan/websites/{websiteId}/traffic-quality/preview` 接受 `policy` 与 `range`，通过共享网站锁复核管理权限，在同一快照内计算当前和拟议结果。预览不写入策略、历史分类或缓存版本。保存接口允许附带 `expectedRevision`，冲突返回 409；旧客户端省略该字段时保留原有保存行为。每次保存原子写入操作者、前后配置和版本历史。界面恢复历史配置先载入草稿并预览，再生成新版本。

审计新增 `totals`、`diagnostics`、`history` 和 `nextCursor`，保留旧 `page` 查询。游标绑定站点、时间、筛选与策略版本，使用事件时间的微秒精度和事件 UUID 排序。前端只在打开、切换条件和手动刷新时读取。

诊断计数与事件、属性、收入、质量证据和去重凭据在同一事务中提交。成功新增、其中带 UUID 的新增、成功去重分别计数；冲突、参数校验失败、数据库失败和未到达采集接口的请求均不进入分母。计数按服务端接收分钟和 32 个分片存储，响应返回实际分钟桶边界、采集起点和保留起点。零分母比例返回 null，未采集的历史显示缺失。新诊断只覆盖 PostgreSQL 网站事件和性能事件，保留 30 天。

## 浏览行为观察

`GET /api/liekan/websites/{websiteId}/traffic-quality/risk` 提供独立观察结果。规则 `browser-behavior-v1` 使用原有会话与访问标识，对已经去重的浏览 PV 分析接收时间和路径重复特征；新增证据不保存完整 UA、原始 IP 或访问路径。观察结果不参与 `standard` 或 `strict`，也不写回 `suspected`。

窗口为五分钟，每分钟推进，延后两分钟处理，为采集事务提交留出余量。持续高频需要一分钟至少 60 PV 且窗口至少 120 PV；机械节律需要至少 30 PV、至少 60 秒跨度、间隔中位数 0.5–10 秒、相对中位绝对偏差不超过 5%，且至少 90% 间隔位于中位数的 ±5%；路径高度重复需要至少 30 PV、至少 60 秒跨度和同一路径占比至少 90%。命中至少两项进入建议核查。网络集中到达、共享标识和正常自动刷新均可能产生线索，数值用于复核。

现有 worker 使用独立 `liekan-browser-risk` 队列，每十秒唤醒，每批最多处理十个网站，每个窗口最多读取 10,001 个事件以检测截断。超过 10,000 个事件的窗口记录部分覆盖，并停止生成该窗口的行为结论。单站异常记录失败状态、退避一分钟并继续处理其他站点。每次写入检查网站状态、epoch 和规则版本；重置删除清理进度和派生结果。历史缺失、队列延迟、未观察窗口及超出 30 天保留期的范围均无法证明无风险。

风险明细按接收时间窗口展示，按当前分类、来源与主机筛选限定匹配访问；特征值来自完整观察窗口。影响预览对选定事件时间范围内的当前有效事件去重，重叠窗口不会重复计数。诊断、观察覆盖和业务事件时间分别标明。

可在应用容器内执行 `node dist/liekan-worker.mjs --observe-browser-risk-once` 处理一个有界批次，用于维护与隔离验收。它使用现有数据库配置，不修改统计策略。ClickHouse 返回显式不支持状态，原生 ClickHouse、链接和像素采集继续沿用原流程。

升级通过追加 017、018 迁移完成。回退使用包含 016 质量过滤的应用基线，保留新增表与原始事件。至少七天真实样本的误报校准独立记录，观察期结束不自动启用行为排除。

诊断计数随范围返回 `complete`、`partial` 或 `missing` 覆盖状态，以及实际观测边界。启用前、过期和未来范围的缺失计数返回 `null`；跨越边界时仅汇总保留范围内已观测的部分。当前分钟按分钟桶显示，失败请求不进入分母。
