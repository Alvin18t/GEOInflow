# 统计缓存与加载体验

猎看统计使用浏览器查询缓存、应用内存缓存、独立 Redis 和 PgBoss 后台预热。数据库保存原始统计和失效版本，缓存保存可重新计算的结果。

## 覆盖范围

| 页面和数据 | 策略 |
| --- | --- |
| GEO 总览、AI 蜘蛛、人类访问、来源、内容、转化 | 缓存页面所需的聚合数据；首次加载显示原页面骨架 |
| 快速发起、AI配置器 | 保留 AI 接口身份校验与 no-store 策略；对话和模型连接按进入与主动操作读取，生成任务沿用有界回查，回答依据使用原有授权快照 |
| 原生统计、事件、UTM、性能、目标、漏斗、留存、旅程、归因、分解、热力图 | 缓存聚合查询，按进入或主动操作读取 |
| 网站卡片、链接来源、图片统计、看板组件 | 缓存汇总；参数、站点、资源和公开权限分别组成查询身份 |
| 分享网站和分享看板 | 每次 API 检查当前授权；缓存经过公开字段投影的数据 |
| 设置、目标定义、分群定义、账户和团队列表 | 浏览器配置缓存；写入后失效关联查询 |
| 实时数据、访客与会话明细、回放、日志逐行记录、导出、营收逐笔列表 | 直接读取；导出继续使用一致性快照 |

今日数据有效期为 30 秒，历史聚合为 300 秒。包含今日指标的页面使用 30 秒。日期边界按所选时区计算。有效期从开始计算时计时，慢查询和网络传输会消耗这个时间。

普通页面在进入、重新进入或主动刷新时读取。静置、切换标签页、恢复网络和电脑唤醒均保持已有结果，无定时请求或自动补发。服务端缓存到期后，当前页面继续显示本轮快照。切换日期、筛选、站点、空间、搜索或分页按新条件读取；主动读取临时失败保留同范围结果并提供重试，401、403、404 清理相关旧结果。目标、分群等真实空配置显示空状态。

页面读取身份由当前访问与主动刷新轮次组成，内部重挂载和短编号归一化共用本轮身份。相对日期、实时窗口、日志窗口及今日估算基于本轮时点。日志刷新先回到首批，无限列表刷新仅读取首批；未保存输入由现有草稿提示保护，AI 回答流和下一条草稿持续保留。编辑成功更新当前受影响页面，其他关联缓存标记失效后等待进入。普通查询配置集中在 `manual-client.tsx`，产品通过 `contracts/manual-refresh.ts` 使用。

蜘蛛分析登记实际缓存结果的生成时间与期限，主动刷新使用已认证的统计请求上下文。蜘蛛归因与控制接口在 Next 响应头配置中显式声明 `private, no-store`，覆盖默认 API 缓存头及相对 API 前缀；采集接口保持原有策略。

手动刷新使用 `refresh=1`，跳过两级服务端缓存。已开始的普通查询或后台预热结束后，会建立新的手动快照。同轮手动请求合并；同一身份和查询的下一轮刷新至少间隔 5 秒，提前重试返回 429。

入口解析后单独处理刷新控制参数，普通读取、手动读取和后台预热共用同一结果身份。手动更新完成后，新快照会写入共享缓存；后续未命中本地缓存的普通读取可复用它。其他实例按服务端期限复用缓存；浏览器已有结果保持本轮快照，每次主动请求核对权限与配置强版本。查询中的业务属性名及嵌套字段完整保留，名为 `refresh` 的业务字段也参与结果身份。

页面模块策略集中登记在 `cache-policy.ts`，覆盖测试同时对照页面清单与导航契约。新增页面需要明确聚合、配置、明细模块策略。兼容入口使用同一请求有效期、取消和刷新机制。

## 服务端容量和失效

- 每个应用的内存缓存最多 128 项、32 MiB；单项超过 2 MiB 时直接读取。
- 所有未命中的聚合计算共用并发 2、等待队列 32、最长排队 5 秒的限制。超额返回 503 和 `Retry-After`。
- 同一进程内的 API 与服务器渲染共用请求上下文、主库元数据与统计快照、计算名额和错误类型；共享缓存运行时只安装一次，保留正在合并的请求。
- 前台请求预算 65 秒，计算最多 60 秒；事务中的 SQL 串行设置实际剩余 `statement_timeout`。数据库确认 SQL 结束后释放计算名额。
- Redis 的单请求网络预算为 150 毫秒，累计连接与回复的实际等待时间；并行查询重叠的等待区间计入一次，后续命令扣除已用时间和进行中的等待。连接或回复超时会断开连接，进入 10 秒熔断。缺少 Redis 配置时使用内存缓存和有界数据库计算。
- Redis 命中保留原计算时间和剩余有效期；结果支持 Decimal、Date、BigInt，并向每位调用者返回独立副本。
- 原生 SQL 行结果按模板、实际绑定值及时区形成查询键；HTTP 和后台任务中等价的数据库查询共用结果。完整响应继续包含资源、规范化条件、主库版本和访问范围。
- 分布式计算租约为 30 秒，每 10 秒续租，发布和释放均核对所有者。取得租约后再次检查普通结果，避免前一计算刚发布时重复查询。等待其他实例最多 30 秒，使用有界退避；已经观察到活动租约的请求在连接或命令预算结束时返回可重试 503。

迁移 `012_analytics_revision.sql` 保存 website、link、pixel 的强版本和删除墓碑。网站设置、目标、漏斗、报告、分群、重置、删除会在同一写事务递增版本。批量删除用户或团队也递增受影响资源版本。

每个缓存请求从主库核对版本和当前资源访问权；合并请求中的每位用户分别复核。计算使用主库 RepeatableRead 快照，完成后再次核对。强版本变化会丢弃结果并重试一次；持续变更返回可重试状态。仅日志数据版本变化时可返回合法快照，有效期立即结束。

同一请求中，同一轮已准备好的子查询可共用一次主库复核；资源、身份、访问范围及复核模式必须一致。开始主库查询前关闭本轮合并窗口，稍后到达的结果另行复核。复核结果仅用于这一轮，期限取参与查询中最早的截止时间。

页面报表和分享报表接入运行时后，由完整版本向量决定日志数据与策略的缓存身份，并在返回前复核。兼容的单层缓存路径保留独立日志版本查询，使数据和策略更新继续改变结果身份。

追踪器高频事件继续按短有效期更新；日志导入按已有批次数据版本失效，保持原追踪器与 SDK 协议。

## 分享页

公开分享首次进入、恢复可见时先通过网络验证当前授权。可见期间每 30 秒验证一次。授权期限独立于统计快照；离线且授权期限结束时隐藏数据。验证成功保持普通查询身份，授权范围变化清理旧数据并等待用户主动读取。

查询身份包含分享范围、资源集合和看板布局指纹。名称或凭据轮换可复用同范围的有效数据；范围变化清理旧查询。每次 API 在读取缓存前和返回结果前验证分享状态、密码证明和公开权限。

统计响应设置 `private, no-store`，浏览器仅在当前查询缓存中保存数据。CDN、Service Worker 和持久化浏览器存储不保存公开统计结果。

## 部署

`docker-compose.liekan.yml` 提供 `analytics-cache` 和 `analytics-worker`：

- Redis 7.4，仅在容器网络内开放，256 MiB 缓存上限、384 MiB 容器上限，使用 `allkeys-lru`，关闭数据持久化。
- 后台进程使用同一应用镜像，入口 `dist/liekan-analytics-worker.mjs`，并发 1、CPU 1、内存 512 MiB。
- 后台统计连接池最多 2 条，PgBoss 连接池最多 2 条。
- 应用启动不依赖 Redis 健康状态；应用先完成数据库迁移和队列初始化，后台进程再启动。

独立部署设置 `LIEKAN_ANALYTICS_REDIS_URL`。原有 `REDIS_URL` 继续服务登录、会话等原用途。使用不同 Redis 实例承载统计缓存和身份数据。

迁移只增加版本表。升级沿用当前猎看数据库，保留用户数据和自定义登录凭据。停止后台预热或缓存服务时，应用仍可通过有界计算返回结果。回退应用版本时保留迁移表和数据库卷。

## 后台预热

队列名称为 `liekan-analytics-refresh`，沿用已有 `liekan_jobs` PgBoss schema。任务包含校验后的查询条件、资源、版本、范围指纹和身份引用，不保存 HTTP 凭据、密码、访客 IP 或 SQL。

热门组合在 15 分钟内至少出现 3 个访问轮次后登记，每站最多 4 个。今日结果提前 5 秒预热，历史结果提前 30 秒。相同组合的 queued、active、retry 任务去重；热门访问停止 15 分钟后结束预热。后台更新不延长真实访问窗口。

独立维护循环只读取已登记的到期需求。计算完成安排下一轮；提交后的版本失效合并最新需求。每站最多 30 秒一轮，全局每分钟最多 20 次实际聚合计算。后台任务按原 `scheduledAt` 判断迟到，最多迟到 30 秒，失败固定间隔 5 秒额外重试两次。Redis 不可用时暂停预热，队列生产失败保持前台读取和已提交写入有效。

后台组合查询依次执行当前区间和对比区间，共用任务的 30 秒期限，避免同一任务的子查询互相排队。

## 验证与观测

统计 API 返回以下诊断头，可在浏览器网络面板查看：

| 响应头 | 含义 |
| --- | --- |
| `X-Liekan-Cache` | hit、miss 或 coalesced |
| `X-Liekan-Cache-Source` | memory、redis 或 database；与方案中的缓存来源一致 |
| `X-Liekan-Cache-Tier` | memory、redis 或 computed；复合响应可包含多层 |
| `X-Liekan-Generated-At` | 最早计算开始时间 |
| `X-Liekan-Expires-At` | 复合响应中最早失效时间 |
| `X-Liekan-Server-Time` | 返回时服务器时间，用于浏览器保守计算剩余时间 |

`pnpm liekan:verify --working-tree` 检查冻结依赖、类型、API 生成一致性、测试、原视觉参考和生产构建。开发工作区检查与正式发布检查分别记录。

`pnpm liekan:cache-benchmark` 创建独立容器、数据库卷和明确标记的合成数据，完成后清理自身资源。默认验证 100 万事件和 100 万日志、10 个网站、30/90/365 天范围，每场景 200 次请求；`--smoke` 用较小数据验证链路，`--extended` 使用每类 500 万行。另加入有确定预期的事件属性、访问序列、回访、收入、热力图、链接和图片追踪数据，报告记录各表实际行数。可用 `--image` 选择已构建镜像，`--baseline-image` 在同一隔离数据集上测量旧镜像。

验收矩阵包含事件及属性展开、UTM、临时和已保存目标、漏斗、留存、旅程、归因、分解、性能、收入、点击与滚动热力图、批量网站汇总、链接和图片追踪图表、来源分页、GEO 的十个聚合资源分支与公开分享。合成日志覆盖训练、搜索、用户触发、未知和异常请求；目录包含分类、发布时间、抓取深度及结构证据；来源区间、国内外地区和多类引荐具有确定预期。日志明细单独验证过滤、100/100/40 行分页、前后游标与自动来源覆盖规则。缓存路径逐字段对照直接计算结果，核对实际响应来源；后台政策允许的组合同时验证预热。会话、收入、属性、旅程和日志明细通过写入或修改后再次读取验证新鲜性，分页使用真实非空数据。

基准单独记录另一个实例首次使用接口的服务加载时间，再用不同查询键测量共享结果命中；首次记录保留完整正确性检查。四种延迟路径和匹配的旧版对照均使用并发 1，单独验证 50 人同键并发；旧版附加开销按 200 对相邻请求测量，准备与测量顺序一起交替，两边各自预备缓存后计时，记录全部准备结果及实际尝试数。原分批对照完整保留，附加开销目标固定为 30 毫秒；各场景记录并发数，Redis 准备阶段与测量阶段的查询计数分别记录。基准分别记录未缓存、内存、Redis、预热后的 p50、p95、p99、全部请求结果、数据库查询、响应大小和容器占用，并检查跨实例失效、共享计算、租约、类型还原、Redis 故障恢复及 PostgreSQL 实际超时终止。预热验收核对生成时间晚于本轮调度时间，并在清空应用内存后读取 Redis 结果。合成热门资格仅用于隔离测量后台执行路径；访问频次和调度政策有独立真实 Redis 测试。

数据库计数以 PostgreSQL 实际语句调用次数为单位，分别记录分析源读取、其中的聚合语句、持久版本读取及权限和资源元数据读取。来源表采用完整表名匹配，包含事件、属性、会话关联、收入、热力图、回放和 GEO 日志及目录；聚合同时识别分组、计数、求和和分位数等函数。写入、建表和统计观察语句排除，含分析源的语句归入分析读取。准备阶段的计数单列，50 人并发的预期值查询在测量前完成。预热测试先启动空内存的应用实例，再执行后台任务，保留结果原有有效期。

浏览器验收使用独立上下文和固定时区，等待真实非空数据与图表绘制，记录首次进入、有效历史缓存切换、兼容统计入口及公开分享的实际请求范围与有效期。每轮分别记录请求、错误和取消；分享还检查持续停留的授权续期、断网后的到期遮蔽与恢复，以及兼容分享入口。主基准运行原始 11 个页面、22 个图表的视觉参考检查。临时网络使用空闲专用网段；清理只处理本轮确认创建的容器、网络和卷，同时移除这些容器的匿名临时卷。Redis 准备响应保留状态、耗时及缓存诊断；失败时先保存本轮容器日志，脱敏后清理。所有计时结束后，通过实际统计函数捕获最终 SQL 和绑定，在独立只读事务中采集完整执行计划、缓冲区与索引信息；这些计划耗时单列。

热路径验收目标为 API p95 ≤250 毫秒、p99 ≤500 毫秒。本轮未缓存计算 p95 ≥500 毫秒的场景要求至少降低 60%。候选内的计算与命中比较记录复用收益；提供旧镜像时，对旧版 p95 <500 毫秒且响应契约匹配的场景检查额外开销 ≤30 毫秒。旧镜像缺少接口或契约不同的场景单独列为无法比较。基准报告保存在本地 `outputs/`，任何失败均记录为未通过。线上体验取决于实际数据分布、数据库容量、网络与缓存命中率，应以测量结果判断收益。

正常场景要求全部 200 次响应正确。Redis 中断场景单独保留 200 次尝试，区分正确的数据响应和受控的 503；后者必须在请求预算内返回匹配的错误状态、明确消息、`private, no-store` 及有界 `Retry-After`。连接失败、客户端超时、其他错误或错误的数据响应均使故障验收失败。Redis 恢复后仍须验证正确数据和跨实例共享命中。

今日卡片的压力测试在当地日界线变化时读取新的真实对照，按响应生成日选择对照，前日快照仅在原有 30 秒有效期内允许复用，并记录日界线及校验耗时。分析源最大时间在准备阶段核对；新对照使用同一冻结数据集。校验耗时与 API 响应耗时分别记录，日界线对照读取的数据库活动仍包含在明确标注的计数范围内。

内存命中场景在计时前独立计算一个数据等价的新结束时间键，核对全字段、实际范围和原有有效期后连续测量，避免复用较早场景已经消耗的有效期。准备结果和参数单独保存；旧版附加开销继续以相同 URL 的相邻配对测量判定。所有计时结束后，用普通追踪事件写入分别验证原生统计、私有页面、公开分享和补充事件分析的手动刷新：强版本保持一致，手动读取得到新增数据，随后两实例的普通读取命中同一新快照。

正式 `pnpm liekan:verify` 在隔离数据副本执行逐页手动读取验收：覆盖功能清单与实际页面文件，核对十分钟、焦点与网络恢复零普通请求、主动刷新和重新进入。网站管理、GEO 总览、实时访客和日志另进行真实十分钟静置，新增合法追踪事件验证主动刷新取得变化。静态、身份和状态入口分别记录无需普通读取的原因。
