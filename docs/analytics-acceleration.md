# 统计加速

GEOInflow 使用 PostgreSQL 中的持久汇总、访问事实和覆盖清单减少历史数据的重复计算。原始事件、日志和核验证据继续保存。当前尾部、无效桶和覆盖缺口按原始事实补齐；范围 UV 在合并访问事实后精确去重。

## 启用和历史构建

运行正常的应用及 `analytics-worker`，完成增量迁移后，新网站和升级后新增输入自动进入维护。网站管理者可从网站管理或网站设置打开 `/settings/analytics-acceleration`，选择网站，查看覆盖和任务记录。

历史构建支持三个范围：

- 常用报表范围：所选时区近 30 天、对比期和六个自然月趋势的共同依赖。
- 自定义范围：开始日期包含，结束日期不包含，日期按所选时区解释。
- 全部留存历史：冻结提交时仍保留的事件及日志边界。

进度来自已完成工作单元。关闭页面后任务继续运行。构建暂停会保留新增输入捕获；停用加速会关闭该网站捕获并使旧覆盖退出读取。重新启用建立新的 epoch 和捕获基线，历史范围需要重新构建。管理操作使用 UUID 幂等标识和修订号，过期操作需要先读取最新状态。

## 数据层和精确口径

| 层 | 内容 |
| --- | --- |
| 原始事实 | 现有事件、会话、日志、质量及清洗证据 |
| 变更捕获 | 同事务、语句级触发器登记 32 路叶桶修正标记 |
| 日志汇总 | UTC 5 分钟及小时低基数计数，小时路径与身份事实 |
| 访问事实 | UTC 小时内匿名 session/visit、主机、PV、custom、最早/最晚时间及支持维度 |
| 覆盖清单 | epoch、规则和清洗版本、输入指纹、候选代次与已验证空区间 |
| 展示结果 | 浏览器、进程、Redis 和持久查询任务，独立保存计算时间与有效期 |

新增大型派生表按 UTC 月分区。原始表沿用原结构。五分钟任务维护低基数计数，完整 UTC 小时关闭并经过 30 秒缓冲后构建小时路径；当前小时和旧的非整小时路径覆盖使用原始事实。候选全部完成并通过版本和租约复核后才原子发布。迟到、更新、删除、清洗发布及相关维度更正使受影响覆盖退出读取，后台再构建。

分析触发器绑定安装时的数据库 schema，独立的新连接也能正确处理 ORM 写入。替换触发器函数时需重新指定其 `SET search_path`；PostgreSQL 的 `CREATE OR REPLACE FUNCTION` 会清除本次定义省略的函数配置。变更捕获持有站点代次锁，停用和重新启用与事实事务在同一边界串行。独立数据库维护若与生命周期操作冲突，会以 SQLSTATE `55P03` 原子回滚；维护方应按网站、加速状态、子表的顺序取锁，并在冲突后重试完整事务。

普通 `/api/send` 事务保持回执、单条原始事件、地理及质量证据的原子顺序。每站固定 32 行访问锁，同一访问在原始事件入口等待前一事务提交后再读取邻居快照；证据映射先锁定原始事件，更新、删除和全族失效遇到冲突时以 `55P03` 原子回滚。链接和像素没有分析站点元数据时继续采集。

多语句、多事件维护应先按网站 ID 顺序取网站 `FOR UPDATE`，再操作分析站点及事实；现有重置、删除和清洗入口沿用此边界。直接 SQL 和开发模拟脚本执行多事件事务时也需要该维护围栏。任意无围栏的多语句 SQL 仍可能因后续语句扩展脏标记集合产生死锁，调用方应重试完整事务。滚动升级保留原采集事务顺序。

访问级事实跨小时合并后计算 UV、访问、跳出和时长；custom-only 访问和主机分组沿用原查询含义。日志保留归档身份、目录版本、原用途、AI 资格三态、识别、核验和自检维度。历史身份缺失保持未知。

浏览器设备维度与身份依据来自事件自身的采集快照。访问事实同时保留人口事件数及身份、规则、目录版本；custom 和 performance 事件参加人口完整性判断，PV、访问、跳出和时长继续各自的筛选口径。人口元数据按完整网站时间窗计算，筛选和分页后的指标仍使用该时间窗的身份可用性。身份依据不完整时，访客、访问等身份指标显示不可用，PV 与收入保持可计量。

人口事实使用新的汇总语义版本。旧代次保留供检查，新读取会拒绝使用旧版本覆盖。事件环境更正定位到受影响访问；当前 epoch 内的治理排除确认、撤销和活动成员变更使访问覆盖退出读取。结果缓存沿用强版本失效，普通单点更正保留定点重建范围。

收入资格校验按网站与收入事件定位有效事件，避免对每笔收入重复展开整站事件；来源策略、清洗结果和治理排除继续参与同一校验。

查询能力由现有 schema 和指标族控制。基础日志计数、状态、身份、路径、趋势和原生基础访客计数及支持分布可使用汇总。高级过滤、顺序、归因和未支持条件使用原查询。复杂报告继续在同一个数据库快照生成。v1 AI 日志采用半开边界，兼容查询保留包含上界的原精度条件。

GEO 评分公式、证明标准、日快照、计算依据和趋势保持既有协议。GEO 后台计算参加共享准入，读取快照独立于历史汇总构建。

## 异步读取和缓存

兼容的私人聚合 GET 可携带 `Prefer: respond-async`。已有可用结果返回原 DTO 和 HTTP 200；冷查询登记持久任务并返回 HTTP 202、`analysisJob` 和 `Retry-After`。客户端轮询状态，完成后读取原结果。202 和错误均不写入成功结果缓存。

任务仅接受完整私人登录和当前网站权限。提交、执行、状态及结果读取都复核权限、网站生命周期、强版本和 epoch。消费者只能读取自己加入的任务。公开分享、API key、部分 2FA 身份不进入新任务协议。未携带偏好的调用方继续原协议；ClickHouse、链接和像素沿用当前路径。

结果新鲜度与保留期分别计算：今日相关结果 30 秒，历史结果 300 秒；来源缓存的较早有效期继续生效。读取不会延长有效期。成功任务保留 24 小时，每站保留最新 20 份成功结果，单份最多 2 MiB。过期结果只能作为有时间说明的上次结果，当前任务继续计算。

持久任务在内部同时保存结果及其人口元数据，容量上限包含两者。读取、缓存预读和后台任务完成时恢复同一结果对应的元数据；数值与元数据在同一个报告快照中读取。原生数组的 JSON 结构保持不变，人口摘要通过既有响应头传递。

原生统计、访客分布、热力图、已保存目标和批量趋势图以完整快照保存结果及人口依据。批量趋势图核验并绑定全部资源版本，各资源的人口依据保留自己的资源标识。手动刷新将新结果写回相同条件的常规缓存键，后续普通读取即可复用。

浏览器后台页暂停轮询，退出页面会取消当前读取，数据库任务保持可恢复。前台累计查看 15 分钟后显示继续查看按钮。手动刷新触发新的计算；相同条件的普通并发请求复用活动任务。

## 工作预算和容量

查询任务的全局活动上限为 32，每站 8，每个消费者的普通看板与其他分析各 2，网站与全局上限共同约束两组任务。真实前台任务使用相同队列优先级10，后台预热使用低优先级0，热力图单次计算预算为 10 秒。重复加入同一任务不重复占用该消费者名额。固定 PgBoss 队列负责唤醒，数据库业务任务是可恢复的真实状态。

所有重分析进程共享一个数据库重计算租约，租期 90 秒，每 15 秒续期。显式查询和 GEO 优先；增量等待 30 秒后获得下一个短单元；历史工作等待时，每五次交互让出一个单元。预热在空闲时执行。等待租约不占用数据库连接。

交互查询获得准入后最多计算 60 秒。构建 SQL 预算 5 秒、事务 30 秒；每批初始 2,000 条，失败时缩小，最小 100 条；最多四次尝试，退避 5、30、120 秒。单次队列交付可连续处理有时间和数量上限的短批次，每批释放并重新竞争共享名额，同类任务按等待时间轮转。停机信号、交互任务和构建权限均在批次之间复核。旧 worker 丢失租约后不能发布。

增量发现单独保存网站检查时间和五个固定的族游标，覆盖日志与访问的叶桶、失效覆盖及日志小时合并。每轮最多检查八个有候选的网站。每站五个族分别检查最多 32 个最新元数据桶和 32 个历史游标桶，每段最多尝试入队一项，合计最多 80 次入队尝试，低基数候选优先。最新范围和历史游标各自推进，新增关闭桶可及时进入维护。检查后推进游标；相同失败请求未重新入队时也让出下一轮名额。检查时钟、实际执行时钟和七天清理时钟分别保存，重启后继续轮转。

每站派生空间采用 1 GiB 保守预算，实例派生表、分区和索引采用 8 GiB 实际预算，包含候选和保存结果。候选清理保留当前及前一个代次，超过七天的废弃代次受控回收。

路径或访问事实只有在三个完整日的实测对照都满足以下条件时停止继续扩展：派生行数超过输入行数的 80%，且冷读取提升不足 20%。缺失、超时或结果不等价的样本不会触发停止。已有覆盖继续可用，缺口保持精确读取，低基数计数继续维护。

## 部署和排查

使用现有 `scripts/liekan-deploy.sh` 部署应用和分析 worker，保留已有配置、数据库凭据、容器大版本及数据卷。PostgreSQL 15、16 都支持本功能。升级现有 15 实例时继续运行 15。新增服务、账号和必填环境变量为零。正式镜像使用项目的 `Dockerfile.liekan`，沿用已有的构建内存设置。分析 worker 的运行预算保持 1 CPU、512 MiB。

部署脚本在镜像构建成功、原数据库和缓存健康后，先停止旧 worker，再更新应用及执行迁移，应用健康后启动新 worker。迁移按完整文件名和校验值识别；保留 `037_analytics_rollups.sql` 与 `037_browser_population.sql` 各自的历史记录，不手动改号或删除已应用文件。

迁移执行器在取得事务锁前及每条原始迁移语句前设置 2 秒锁等待上限。已有迁移文件中的会话设置保持原样执行，后续 DDL 使用统一上限；锁竞争失败会回滚本次迁移事务，可在冲突释放后重试。

页面长期排队时先检查 `analytics-worker` 心跳、固定队列、任务错误码和共享租约。覆盖变为待更新时查看是否存在清洗、策略或来源更正，并核对后台构建进度。容量受限可暂停历史构建或停用网站加速；原始事实继续用于统计。原始输入已删除的历史无法凭汇总创造新的核验证据。

验证入口：`pnpm test:analytics-rollups` 在自有临时数据库中执行真实汇总、访问去重、无扫描覆盖、失效和持久任务对照；`pnpm liekan:verify --working-tree` 验证源代码、生成物和生产构建。缓存容量与规模验证见 [统计缓存](analytics-cache.md)。所有基准数据必须独立命名和隔离，结果按实际运行记录。

## 持久看板快照与当前数据更新

迁移 049、050 增加私人看板的持久结果与浏览器访问、路径事实。普通看板读取只检查当前身份、网站权限、强版本和快照身份，然后返回已发布结果。进程与 Redis 缓存失效后仍可复用数据库中的结果。首次出现的新条件通过原有持久任务协议后台生成；逐行记录、导出、公开分享和 GEO 日快照继续采用各自协议。

今日普通看板使用已闭合的 UTC 三十秒窗口，读取时保留精确的当前尾部与覆盖缺口。最近使用的组合优先进入更新，首次读取、自动读取和主动刷新可登记后台计算，旧结果在计算期间继续展示。页面每 30 秒读取并显示实际截止时间；实时页每 10 秒读取原实时接口。隐藏和离线暂停，读取未完成时合并等待。热力图、留存、归因等重分析保留五分钟后台窗口。原有 UTC 五分钟及小时汇总粒度、迟到修正、人口完整性、质量资格与 UV 去重规则保持一致。

历史结果按输入与规则版本复用。后台检查范围内的变更证据，稳定历史保持原有结果；迟到、补录、删除、属性、收入、热力图及质量依据变化会触发受影响结果更新。三十秒展示修正标记与原始写入在同一事务提交；五分钟分析汇总标记保留原有粒度，采用 32 路分片，不保存 IP 或完整 User-Agent。已完成批次的发布边界排除截止时间之后的新事件。任务登记与其快照绑定在同一事务提交，发布前再次核对输入、权限、强版本、epoch 和原有计算租约。失败或等待期间保留已有的合法结果。

后台自动登记全部留存事件与日志的历史边界，按日推进持久游标，复用有界构建单元。尚未关闭的最后一小时等待关闭后继续处理；进程重启保留游标，失败任务按退避恢复。自动历史使用历史调度通道，今日增量与迟到修正可以独立推进。停止或重新启用网站加速继续使用现有 epoch 围栏；停用时恢复原有异步精确读取。

浏览器事实保留跨桶精确合并所需的 session/visit、首末事件、来源、设备、地理与路径统计。常用总览、趋势、来源、地域、设备、路径和普通目标计数读取已验证代次，边界缺口按原始事实补齐。跨日 UV 按身份去重，时长与跳出在合并访问后计算；复杂漏斗、顺序与未支持条件继续使用原有后台查询。原始事件与核验证据沿用原保留策略。

默认页面会预先登记，并记住近期使用的时区和语言；预热不改变真实访问时间，队列空闲时每轮最多启动一个冷计算。最近两分钟实际读取的组合采用三十秒更新，无人查看的当前常用组合采用五分钟维护，其余闲置组合保留结果并停止主动计算，已发布截止时间保持单调。跨天后预热新日期的默认组合，上一日已发布代次保留，旧的今日指标快照停止热更新；昨日尚未完成的统计在闭合后发布历史结果。数据库中的每个网站默认保留最近 200 份已完成普通快照，运行中的任务继续受队列名额限制，按最近使用回收，单份与整站空间沿用现有容量保护。重置、删除和权限变化继续围栏旧结果。

迁移 051 为事件、明细、原始日志和日志核验证据增加三十秒发布围栏，保留历史粗标记及全局失效。迁移先等待相关源表写入结束，再替换捕获函数并重绑 schema；旧迁移和原始事实保持原样。

迁移 052 补记跨时间的访问依赖：同一次访问的资格变化会重新校验此前热力图，升级后首次补全的会话身份会重新校验此前身份筛选。后续稳定身份采集沿用已有截止围栏。已保存结果保留显示值并重新进入后台校验。预热任务被前台读取后更新队列中的实际优先级，保留原任务与输入。

### 常用日期与后台需求

常用页面按现有日期选择器预热今天、近7天和近30天；每轮空闲维护只登记一个冷任务，预热不更新真实访问时间。200条持久结果满额时，在网站容量锁内为缺少的当前常用组合回收闲置旧结果，按最近读取顺序淘汰。最近两分钟读取的结果、关联计算任务的结果和当前常用组合受到保护；全部位置都受保护时保留既有结果，后续维护再尝试。前台新条件登记沿用相同保护约束，优先淘汰闲置旧结果或版本失效的结果；容量无法释放时保持原有空间限制。今天的逻辑窗口跨小时复用；跨日后按所选时区预热新的今天、近7天和近30天，旧窗口按相同容量规则回收。

冷预热和已发布结果维护逐轮轮转，防止一方持续占用后台登记机会。当前常用组合在无人查看时继续按五分钟维护，其他闲置两分钟的组合停止主动计算并保留已发布结果。用户返回时，权限、强版本和代次继续核验；依赖边界、截止时间及输入指纹均未变化的已发布结果直接复用，变化时重新入队。迟到数据继续经过原有更正和发布围栏。有自动读取的今日普通看板立即返回同站点、同权限版本、同条件的已发布结果，并保留真实数据截止时间；到期结果在后台更新。主动刷新、历史更正和无自动读取的重分析页面通过既有任务句柄继续跟随新结果。

迁移053增加正在查看的普通看板首次计算的独立全局单名额，查询预算10秒；无人查看的预热和维护使用低队列优先级与原重分析名额，首次查询仍受10秒预算约束。失败后的重试沿用原重分析名额和预算。正在查看的任务通过已授权状态读取维持需求。离开页面两分钟后，失败任务和已失败的重试暂停，已有结果保留，重新打开页面恢复登记。后台任务不再为无人查看的失败结果循环创建新的重试批次。


### 统计查询执行策略

普通看板、原生统计及浏览器明细组合查询在当前报告事务中设置 `SET LOCAL jit=off`。覆盖代次、缺口补读和质量视图展开后，短查询的计划估算可能触发大量 LLVM 编译；事务内关闭 JIT 可避免这部分固定开销。事务结束后数据库恢复连接原有设置，查询范围、质量资格、覆盖围栏与统计表达式保持一致。

分析工作进程的主连接池固定为三个连接，为两个计算保留一个权限、租约与队列控制连接。计算闸门与数据库许可对应：正在查看的普通看板使用独立的单名额，其他重计算沿用原有闸门。每个计算名额继续执行原有超时、权限和发布检查，等待中的同类请求保持有界。


前台统计请求派发遇到计算名额占用时，队列按1秒间隔进行最多10次派发重试；重新领取前不增加统计计算次数。统计计算总计最多四次尝试，退避沿用原规则，闲置失败任务继续暂停。首次实时预热交付预先配置相同的派发重试，用户在队列领取后打开页面时可直接衔接。后台预热继续使用低优先级与重分析名额。持久任务的五秒补发维护保留，用于队列中断与丢失交付的恢复。

页面与内容仅请求旅程、退出页时采用相同资格与时间边界的窄事件投影，避免重复展开未使用的会话和地域维度。访问旅程的首来源按完整所选窗口与既有时间、事件 ID 排序预先提取；回放列表先限定已录制的访问后聚合。转化归因在一次事务查询中复用相同的转换事件与归因时间，保留各来源分组、独立会话计数、时间相等边界及身份缺失处理。

迁移054保持回放资格的同网站、同会话、同访问 EXISTS 条件，并加入 OFFSET 0 约束资格探查，避免优化器先对全站有效事件生成访问集合。既有迁移保持不可变，升级保留原始事件、录制与已发布统计。

前台交付使用同一优先级；计算名额暂不可用时，工作进程按已领取的交付代次完成失败重派，并将该次等待交付降为低优先级，给其他可运行页面让出领取机会。统计业务行仍保持排队且不消耗计算尝试。排队交付更新继续受 PgBoss 的状态和代次围栏限制。

PostgreSQL 加速启用时，当前月留存的完整月份起点与已闭合五分钟窗口共享快照。请求登记时捕获的闭合上界固定为统计结束点；跨窗口的新读取使用新快照，延迟登记与后台维护不扩大这个范围，迟到更正继续沿用输入围栏。明确的过去子月范围、未闭合首个窗口、未来月份、关闭加速及 ClickHouse 保留原请求范围，页面的读取时刻与“待观察”判断保持一致。

所有前台统计的首次排队与首次运行按一秒检查结果，避免轻查询在统一三秒检查间隔中累计等待；实际计算失败后的排队与后续运行继续采用三秒检查，计算次数和失败退避保持原值。HTTP Retry-After 与任务句柄中的检查间隔保持一致。

来源关键词使用省去地区、环境维度的访问投影，默认访问查询保持原 SQL；入口归因、访问指标、目标匹配、同站会话所有权和脱敏规则不变。收入交易列表的选定会话条件保留相关索引探查，避免每笔交易重复扫描统计窗口；跨访问的会话归属、币种、日期与金额精度沿用原规则。
